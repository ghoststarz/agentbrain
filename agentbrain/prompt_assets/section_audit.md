## 任务：夜间小节体检（section_audit）

你会收到同一篇长期笔记受管块里的所有 `### 小节`（含标题、可选 `section_key`、正文前 120 字）以及被自动标出的高相似候选对。

你的唯一任务是判断：**候选对里有没有实际上在讲同一件事、应该合并成一节的小节**。

### 硬性规则
1. **拿不准就不要合并**。只有当你明确判断两节（或多节）讲的是同一个主题/同一组约束/同一个机制的不同版本或重复表述时，才合并；如果只是词汇相近但讲的是不同方面或独立子主题，保持原样不要动。
2. `keep` 和 `retire` 里的每一项都必须是输入列表里**真实存在、逐字一致**的小节标题，绝不能自造标题，也不能把同一个标题同时放进 `keep` 和 `retire`。
3. **不许编造新事实**。`merged_content` 只能压缩、去重、整理既有小节里的事实与约束，保留最新最具体的结论，长度不超过 300 字。
4. `section_key` 可选：若保留节或被并入节已有合适的稳定 `section_key` 可沿用，也可给出简洁的英文点分键，不确定就省略。
5. 只输出一个合法 JSON 对象，不要输出 Markdown 代码块标记，不要输出任何额外说明。

### 输出格式
```json
{
  "merges": [
    {
      "keep": "<保留的小节标题>",
      "retire": ["<并入后删除的小节标题>"],
      "merged_content": "<合并后的正文，≤300 字>",
      "section_key": "<可选，沿用或新给>"
    }
  ]
}
```

如果没有任何需要合并的小节，直接输出：
`{"merges":[]}`
